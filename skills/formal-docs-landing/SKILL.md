# 正式落盘

## 判据

看读代码的效率是否低于读文档。

- 应用服务接口这类，代码本身说得清，不另写。
- 统一语言、领域边界与职责、领域协作图和上下文图，读代码反而慢，必须长期维护。

## 三层

产品文档，项目顶层文档，治理领域包组的架构、规格、技术与领域文档。三层都走文档评审。形式化的定义、模型与证明同样落盘并验证。

## 文档评审

评审用确定性判据，不做对抗性评审：落盘遗漏（设计里定了、文档里没有）、工作日志式表达、断链、下层违背上层、该有图没图。评审者拿到的是设计产出清单和文档，逐条核，不评价写法好坏。断链检查命令从项目接入点取。

## 这一步完成即交接点

长期维护的知识已进唯一源并过评审，人可以把注意力移开。
