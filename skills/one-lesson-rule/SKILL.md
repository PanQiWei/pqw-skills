# 一堂课法则

一程自主交付常常很长，上下文会反复压缩或累积而腐化。本法则不假设主代理能自己察觉腐化，用时间盒强制从顶层回看。它是机制，不只是原则。

## 机制

主代理进入自主交付期时，派一个便宜的子代理常驻会话后台，叫它哨兵。哨兵不是时刻活跃的。

| 环节 | 谁 | 做什么 |
| --- | --- | --- |
| 定时唤醒 | 哨兵 | 用宿主的原生机制定时唤醒自己：宿主能挂 cron 或定时器就用 cron 或定时器；只能写脚本的宿主用后台脚本定时循环。 |
| 醒来整理 | 哨兵 | 整理本会话边界内工作的增量进展与总体情况：哪些切片完成，哪些在跑，子代理各跑了多久，有没有停滞或反复。 |
| 汇报 | 哨兵 | 把整理结果交给主代理，然后回到休眠。 |
| 回看 | 主代理 | 据汇报从顶层做结构性回看，决定动作。 |

哨兵绝不自己轮询。每次唤醒之间它不消耗 token。

## 节拍

- 主代理：每 45 到 60 分钟一次顶层回看。
- 子代理：运行到 30 分钟及其整倍数时一次健康检查。

## 回看什么

- 总体进度有没有偏离 spec 与 plan。
- 是不是在某个局部兜圈子。
- 上下文有没有因为反复压缩或累积而腐化。
- 每个在跑的子代理是否健康：推进有没有停滞、输出有没有反复。

## 常规出口

升更强的模型，提推理档位，主代理直接介入指导，主代理接手。回看之后通常接一次向人汇报，调用 Skill 工具加载 `progress-artifacts`。
