# 一堂课法则

一程自主交付常常很长，上下文会反复压缩或累积而腐化。本法则不假设主代理能自己察觉腐化，用时间盒强制从顶层回看。它是机制，不只是原则。

## 机制

主代理进入自主交付期时起一个哨兵。哨兵是 [`scripts/sentinel.mjs`](scripts/sentinel.mjs)，不是模型：它读 plan 的进度总览与工作树事实，写一份增量汇报，然后睡。宿主负责到点触发它，接法见[各宿主的接法](hosts.md)。

| 环节 | 谁 | 做什么 |
| --- | --- | --- |
| 定时唤醒 | 宿主 | 有会话内定时的宿主按 cron 触发；没有的用后台脚本循环，到点只写文件 |
| 醒来整理 | 哨兵脚本 | 读 plan：进度行、当前行、切片表、子代理表、里程碑；读工作树：上次唤醒以来的提交、未提交改动；算信号：停滞、可能兜圈、子代理到检查点 |
| 汇报 | 哨兵脚本 | 写到汇报目录的 `latest.md`，固定格式见[回看记录](review-record-template.md) |
| 回看 | 主代理 | 读汇报，从顶层做结构性回看，决定动作，把结论写进 plan 或汇报件 |

哨兵绝不自己轮询，也不调用模型。两次唤醒之间它不消耗 token。

## 节拍

- 主代理：每 45 到 60 分钟一次顶层回看。
- 子代理：运行到 30 分钟及其整倍数时一次健康检查。哨兵从 plan 的子代理表读开始时间，到点写信号。
- 宿主没有定时机制时，主代理至少在每个切片收口时读一次 `latest.md`，并把这个下限写进 plan 的「预算与回看」。

## 回看什么

| 问 | 看什么 | 不看什么 |
| --- | --- | --- |
| 总体进度有没有偏离 spec 与 plan | 切片表、里程碑计数、提交 | 实现细节 |
| 是不是在某个局部兜圈子 | 当前行多久没变；同一失败重复几次；提交信息是否反复改同一处 | |
| 上下文有没有腐化 | 自己有没有重复读同一文件、忘了早先的决定；回答有没有变短变糊 | |
| 每个在跑的子代理是否健康 | 工作树事实：提交、状态、改动统计、日志尾部 | 子代理的会话记录 |

回看是从顶层看结构，不是重读整段实现。上下文已经腐化时，先调用 Skill 工具加载 `pstack:recall` 从 plan、整程包和提交历史重建现状，再继续。长程无人值守时，决策日志调用 Skill 工具加载 `pstack:show-me-your-work`，哨兵汇报与它互为索引。

## 常规出口

| 出口 | 什么时候 |
| --- | --- |
| 继续 | 进度正常，无信号 |
| 升推理档位 | 子代理卡在同一失败一轮 |
| 换更强模型 | 两轮不收敛，且判定本身没错 |
| 主代理介入指导 | 方向偏、范围蔓延、在做测不出结果的工作 |
| 主代理接手 | 子代理停下没交回，或接手比重派快 |
| 停下问人 | 命中 spec 待决事项里只有人能定的那一类 |

回看之后通常接一次向人汇报，调用 Skill 工具加载 `progress-artifacts`。动作与理由记进[回看记录](review-record-template.md)。

## 一程结束

删掉宿主的定时任务或停掉后台循环；汇报目录按 `cleanup` 处理。
