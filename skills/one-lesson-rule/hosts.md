# 各宿主的接法

哨兵脚本 `scripts/sentinel.mjs` 本身不依赖宿主：读 plan、看工作树、写汇报。宿主只负责两件事：到点触发它，把汇报送到主代理面前。原则是用宿主原生的定时机制，没有就用后台脚本循环；任何一种都不让模型轮询。

| 宿主 | 定时机制 | 触发方式 | 汇报怎样到主代理 | 验证状态 |
| --- | --- | --- | --- | --- |
| Claude Code | 会话内 cron 工具（`CronCreate`），按 cron 表达式把一条提示排进队列，只在会话空闲时触发，会话结束即失效，最长七天 | 主代理进自主交付期时建一条周期任务，提示里写「运行 `sentinel.mjs --once`，读 `latest.md`，按 one-lesson-rule 回看」 | 提示触发时主代理自己跑脚本并读汇报 | 已在真实会话里验证一次性触发（2026-11-07T14:58Z）；周期任务在同一时刻一并触发。注意它只在会话空闲时触发，主代理连续工作时会推迟到回合结束 |
| Codex | 没有会话内定时。有后台命令 | 主代理用后台命令起 `sentinel.mjs --interval 45m`，循环写汇报 | 主代理每完成一个里程碑或切片收口时读一次 `latest.md`；宿主不会主动唤醒它 | 脚本在本机 shell 验证；真实 Codex 会话未验证 |
| Cursor | 没有会话内定时。有后台终端 | 同 Codex | 同 Codex | 脚本在本机 shell 验证；真实 Cursor 会话未验证 |

## Claude Code 的建法

主代理在 plan 写好、第一个切片开工前建一条周期任务。cron 表达式避开整点与半点，例如每 50 分钟一次写成 `7,57 * * * *`。提示固定为：

```
哨兵唤醒：运行 node <技能目录>/scripts/sentinel.mjs --plan <plan 路径> --once，读它打印的汇报路径里的 latest.md，按 one-lesson-rule 做一次顶层回看，把结论写进 plan 的进度总览，需要时按 progress-artifacts 向人汇报。不要重读整段实现。
```

一程交付后删掉这条任务。

## 后台循环的建法

```sh
node <技能目录>/scripts/sentinel.mjs --plan <plan 路径> --interval 45m --subagent-check 30m &
```

循环模式先睡再醒。脚本到点只写文件，不调模型，不发消息。主代理在切片边界读 `latest.md`；没有宿主唤醒时，这是时间盒能做到的下限，写进 plan 的「预算与回看」。

## 子代理的 30 分钟检查

脚本从 plan 的子代理表读「开始」列（UTC 时间），到 30 分钟及其整倍数时在汇报里写一条信号。主代理据此按 `delegate-brief`「等待与追加」看工作树事实，决定追加、升级、接手或继续。
