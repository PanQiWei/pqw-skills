# 闭环：回路越紧越稳

## 主代理在做的是一个反馈回路

看现状，对照应然，动手，再看。回路越紧，偏了越早拉回。控制论的常识是：回路里延迟越大、观测越差，系统越容易振荡或跑偏。

把一件事转出去，等于在回路里插进三样东西：

- **延迟。** 子代理跑半小时，这半小时主代理看不到中间状态，只能等，或者取消。
- **窄而有噪声的传感器。** 主代理只能通过报告看结果，而报告会把失败写得像成功。
- **开环。** 子代理中途走偏，没人纠正，偏差一直累积到交回。

## 什么放在紧回路里

| 这件事 | 放在哪 | 为什么 |
| --- | --- | --- |
| 决定后面很多步的事：类型、签名、边界、全化表、验收判断、根因 | 自己做，每一步都看得见 | 它错了，后面全错 |
| 错了影响有限、末端能用确定办法检查的事 | 可以开环跑一段，末端验一次 | 偏了只损失这一段 |
| 长时间盯一个测量或一条流水线 | 后台任务加完成通知 | 不需要模型在场 |

## 必要多样性

能应付多少种意外，取决于知道多少。接的一方知道得少，应付不了需要上下文的意外。所以放手跑的那一段要写停止条件：碰到规格没覆盖的情况就停下交回，不自己猜。

## 回头看自己也是一个回路

主代理自己判自己不可靠，因为腐化的上下文觉得自己没问题。所以定期回看交给一个独立的、持有同一份 spec 与 plan 的哨兵，按一程预算定的间隔醒来，拿工作树事实对照。间隔就是这个回路的延迟：一程越长、越贵，间隔越要定死，不靠自觉。
