# 闭环：一块多大

## 验收产能是瓶颈

一块该有多大，不由做的一方做得动多少决定，由接的一方验得完多少决定。做出来、接的一方还没验过的东西，是没验收的库存：看着是进度，其实是风险。接的一方离开越久，库存越大；方向一旦不对，这些全是沉没成本。

例：代理一夜做了十个切片，人早上只有一小时，只验得完三片，另外七片就是库存。

人是回路里最贵也最窄的一环。代理做得越快，这一环越窄，人出的错代理做得再好也补不回来。

## 同一个结构在三层上重复

| 谁对谁 | 一块是什么 | 验得完多少由什么定 |
| --- | --- | --- |
| 人对主代理 | 一程 | 人的验收窗口：什么时候回来，有多少时间上手验 |
| 主代理对子代理 | 派出去的一块 | 主代理在不膨胀上下文的前提下，用确定办法验得完的量 |
| 今天的自己对压缩后的自己 | 一个切片 | 一个新上下文里读得完开工包、做得完、验得完 |

## 为什么切得更细不缩短回路

切片收口是代理自己对照 spec 核的，人不在场。切片切得再细，人的反馈回路还是一程那么长。只有一程结束、人上手验过、再定下一程，回路才真的变短。所以超了人的窗口，办法是分程，不是把切片切得更细。

派给子代理也一样：一块大到主代理验不完，主代理就只能读报告、信自述。拆成几块，每块末端都能用确定办法验。

## 落在哪

- 一程的尺寸核对与分程建议，归 `candid-friend` 的「一程的大小」。
- 派出去的一块怎么写简报、怎么验，归 `delegate-brief`。
- 怎样算验过，加载技能 `think-evidence`。
