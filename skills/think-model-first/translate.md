# 建模先于代码：翻成代码的形状

全化表说的是什么必须成立。代码的形状由领域模型与对象模型定。翻译的对照表与精化对照表归 `detailed-domain-design`「从形式化交接表翻译」，这里只讲为什么这样翻、怎样判翻对了。

## 为什么不照着全化表直接写

照着表写，每个操作是一个按状态分支的函数。表有多少格，函数里就有多少分支，加一个状态就要改每一个函数。它对，但难维护。领域建模定概念与边界，对象建模定对象怎样协作，两样每次设计都做，做不做形式化都一样：形式化保证对，这两样保证对的东西写出来简洁、能维护。

## 怎样判翻对了

- 一起守一条不变式的状态在同一个聚合里，由它独占修改。
- 操作的前置条件在边界上解析成更窄的类型，进了这个类型不再判。
- 全化表里每个拒绝与错误，是结果类型里的一个具名变体，不靠到处判空。
- 行为随状态变时，用按状态分开的类型；只有数据随状态变时，用一张表或一个归约函数。
- 翻译之后放不回模型排除了的状态：每条不变式能指到守它的类型或方法。

## 不碰状态时

纯计算没有偏函数可写。最简洁的形状往往是数据加一张表，或一个归约函数。硬拆成类，只会多出一堆只有一个方法的类。
