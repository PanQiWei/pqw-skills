# 单会话研发流

一程研发在一个会话里走完：人主导的定义期，代理自主的交付期，中间一个交接点。本技能只定阶段、顺序、交接点和每个环节加载哪个技能。

## 一句话

先在动手前把不确定性尽量消掉，再把执行放手给代理，再用固定节拍从顶层回看。人的注意力只花在定义边界和高层判断上。

## 阶段与环节

| 阶段 | 环节 | 加载的技能 | 产出 |
| --- | --- | --- | --- |
| 定义期 | 1 需求与不变式 | `requirement-and-invariants` | 用户可见差异、不变式清单 |
| 定义期 | 2 领域影响与顶层设计 | `domain-impact-analysis` | 重点、次要、连带领域；总边界 |
| 定义期 | 3 技术调研与复用 | `tech-research-and-reuse` | 复用、二次开发或自造的结论 |
| 定义期 | 4 形式化守护 | `formal-guard` | 偏函数全化、数理模型、定理；转契约测试的清单 |
| 定义期 | 5 细化领域设计 | `detailed-domain-design` | 领域模型、关系模型、仓储设计 |
| 定义期 | 6 正式落盘 | `formal-docs-landing` | 三层正式文档并过评审 |
| 交接点 | 长期维护的知识已进唯一源并过评审 | 无 | 人可以把注意力移开 |
| 交付期 | 7 spec 与 plan | `spec-and-plan` | spec.md、plan.md |
| 交付期 | 8 前置消熵 | `context-pack` | 整程与每切片的上下文包、技术验证 |
| 交付期 | 9 派发 | `delegate-brief` | 目标、边界、规格、信息包四件齐全的简报 |
| 交付期 | 10 定期回看 | `one-lesson-rule` | 每 45 到 60 分钟的顶层回看记录 |
| 交付期 | 11 切片收口 | `slice-closeout` | 结构读数、差分变异、评审结论 |
| 交付期 | 12 向人汇报 | `progress-artifacts` | 可视化、可上手、用完即弃的汇报件 |

## 规则

- 定义期的顺序不能跳：需求先于不变式，不变式先于领域，领域先于架构，架构先于实施。
- 定义期的厚度随影响范围缩放，但每一步都要有明确的「本次不需要」的结论，不能默认跳过。
- 交接点是物理条件，不是感觉：没进唯一源、没过评审的边界，不算定好。
- 交付期执行走 TDD，不过度设计，不过度优化。
- 各环节技能按需加载，不一次全读。
