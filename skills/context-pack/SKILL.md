# 前置消熵

## 两个尺度

- 整程开工前：便宜的子代理整理整程依赖的上下文信息包；主代理完成关键模块的细化架构设计与必要的技术验证。
- 每个切片开工前：做一份切片开工包，四样齐了才动手。

## 切片开工包

| 项 | 内容 | 谁做 |
| --- | --- | --- |
| 上下文增量 | 这个切片额外需要的上下文：涉及的文件与契约、相邻切片留下的事实、整程包里没有的 | 便宜的子代理 |
| 技术细节设计与验证 | 这个切片的类型、签名、模块边界、关键算法；有疑点的先用抛弃式原型验证 | 主代理 |
| 细化的推进方案 | 把 plan 里这一片的一句话展开成有序步骤：先改什么、测什么、什么时候合回、什么时候派子代理 | 主代理 |
| 里程碑待办清单 | 切片内有里程碑性质的待办，每条可勾选、有完成判据；哨兵和汇报件读它判断进度 | 主代理 |

四样写进 plan 的这一片下面，不另开文件。切片完成时把清单勾完，没勾完的说明原因。

## 为什么

把不确定性从「实施时才发现」搬到「动手前就消除」。信息包一次整理，之后只增补。里程碑清单让进度可见，回看时不用重读整段实现。
