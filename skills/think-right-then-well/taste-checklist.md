# 先做对，再做好：品味核对单

做好一轮的第三样判据。结构读数与差分变异由 `slice-closeout` 的工具给出，这七问由主代理自己核，不派评审，也不做对抗性评审。

每问用代码位置作答：文件与行，或符号名，再加一句结论。答「没有可改的」也要指到看过的位置。只核本片改动碰到的代码。

| 问 | 问法 |
| --- | --- |
| 架构位置 | 每个改动的单元放在它所属的层与模块里了吗？依赖方向有没有反过来？ |
| 领域边界 | 本域的契约与类型里有没有出现外域的词？有没有读别的领域的内部状态？ |
| 单一职责 | 每个改动的类型或模块只有一个变化的理由吗？ |
| 开闭 | 这次加的能力是加了新的实现，还是在旧代码里多加了一个分支？ |
| 里氏替换 | 换掉一个实现时，调用方要不要知道换的是哪一个？ |
| 接口隔离 | 调用方有没有依赖它用不到的方法或字段？ |
| 依赖倒置 | 抽象由使用方拥有吗？高层有没有直接依赖具体的适配器？ |

写在收口清单「做好一轮」一项下面：

```
- 架构位置：<位置>：<结论：改了什么，或没有可改的>
- 领域边界：<位置>：<结论>
- 单一职责：<位置>：<结论>
- 开闭：<位置>：<结论>
- 里氏替换：<位置>：<结论>
- 接口隔离：<位置>：<结论>
- 依赖倒置：<位置>：<结论>
```

一问不适用时写「不适用：<理由>」，例如本片没有多态，里氏替换不适用。SOLID 按真实的变化轴拆，不为拆而拆：一个全化后的纯函数，最简洁的形状往往是数据加一张表，答「没有可改的」就够了。
