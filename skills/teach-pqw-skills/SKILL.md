# 教人用 pqw-skills

人问的是怎么用，不是要你开工。回答他的问题，给一条可以直接发出去的示例提示，说明答案来自哪个文件。一程研发要花真实的 token，什么时候开由人决定。要求干活的消息，例如「用这条流做 X」，不是提问：加载技能 `single-session-dev-flow`，在它之下工作。

## 先弄清他要什么

从消息和对话推断。能推断出来就直接答那一节。推断不出就问一个单选，只答选中的那节：

- 理解这条流的心智模型与哲学
- 第一次走一程，我要做什么、说什么
- 某个环节里人和代理怎样配合
- 跑偏了怎么办
- 接到我自己的项目

同时看两件事，只在影响答案时提：项目 AGENTS.md 有没有「pqw-skills 接入」一节，没有则收口里的结构读数、差分变异、文档检查会按「未提供」跳过；本机有没有装 pstack、ub-mode、mattpocock/skills，没有则引用它们的环节会断。

## 怎样教

从他正在做或打算做的事出发，不从流的第一步讲起。先给最小完整的答案，一两句，停下让他追问；他追问再加一层。讲机制不讲比喻：说清这一步为什么存在、少了会出什么事。三个以上部分的东西分几张图逐步画，每张在上一张之上加一个部分，不画一张全图。不出测验，不说「这里很重要」「关键在于」。用地道中文短句，一句一个意思。

## 心智模型与哲学

先读 [心智模型与哲学](mental-models.md) 再讲。它按这几个问题组织：这条流在解决什么、为什么分两期一点、人的注意力为什么要抽离、为什么验收是确定性的、为什么默认不派子代理、为什么要定时回看、三级与圈外、为什么不走缩水版；最后一节「AI 主导研发交付的心智」十条，给他设计项目自己的合入检查、分支与人审规则时用。回答时只取他问到的那一两条。

## 第一次走一程

按 [谁做什么](who-does-what.md) 讲人的部分：

1. 先判断够不够格，判据是影响范围。不够格就不走，也不走缩水版。
2. 第一条提示写目标、完成判据、已知事实和真实约束，不列技能不列步骤。写法在 [提示怎么写](prompting.md)。
3. 定义期六步，每步代理会问什么、人要拍什么板。人在场，代理不替人认可。
4. 交接点人要确认什么，确认了就可以离开。
5. 离开后人会收到什么、什么时候需要回来。

## 某个环节怎样配合

先读 [谁做什么](who-does-what.md) 的对应行，再读该环节的 `SKILL.md`，然后才答。不凭记忆说一个环节做什么。

## 跑偏了怎么办

| 症状 | 一行纠偏 | 依据 |
| --- | --- | --- |
| 小修也被走了整条流，或大改动没过够不够格就开工 | 「这是小修，不走流」或「先判断够不够格」 | 入口的适用范围表 |
| 定义期代理替人拍板 | 「这个我来定」 | 定义期人主导，代理不替人认可 |
| 定义期跳步 | 「回到第 N 步」 | 顺序不能跳 |
| 交接点过了，代理还一直来问 | 「看交接点核对单哪项没过」；都过了说「可以走了」 | `handoff-checklist.md` |
| 派了很多子代理 | 「派发门三个理由是哪一个」「自己做」 | `delegate-brief` |
| 说完成了但没有证据 | 「对照 spec 验收标准逐条核，贴命令和输出」 | `slice-closeout` |
| 评审变成挑刺，方案越改越大 | 「确定性验收，不做对抗性评审」「不过度设计」 | 入口的验收与自主两条 |
| 一边找对一边打磨，或在一处反复打补丁 | 「先做对，再做好一轮」「找本质解：写出共同前提再推翻它」 | 入口的[写代码的四条](../single-session-dev-flow/SKILL.md#写代码的四条) |
| 哨兵没有消息来 | 哨兵是后台的便宜档子代理，自己计时；宿主派不出后台子代理时退回备用做法 | `one-lesson-rule/hosts.md` |
| 汇报件看不懂 | 「只讲架构层面和前后差别，不讲代码」 | `progress-artifacts` |
| 交付后留下一堆工作树和临时文件 | 「按一程清理，出交付声明」 | `cleanup` |

## 接到自己的项目

在项目 AGENTS.md 写一节「pqw-skills 接入」，逐项填下面的槽位。技能正文里写「从项目接入点取」的地方都读这一节；没填的槽位按「未提供」处理，技能跳过该步并在交付声明里写明，不猜命令。

| 槽位 | 谁用 |
| --- | --- |
| 类型检查与 lint 命令 | `slice-closeout` |
| 改动成员的合入检查（与项目合入检查同口径、只限改动成员、含全部测试层；没有写「同合入检查」） | `slice-closeout` |
| 结构读数的覆盖率文件、范围与带位线（工具自带，`--lcov`、`--scope`、`--cc`、`--crap`） | `slice-closeout` |
| 差分变异的范围与点名文件（工具自带，`--scope`、`--files`；修复轮 `--base` 取上一轮收口头；由 Stryker 执行，只支持 vitest 项目；多包仓库按成员 `--project`，用例导入构建产物的成员加 `--build-command`） | `slice-closeout` |
| 项目合入检查已按整程改动跑结构读数与差分变异时的命令（没有写「无」，一程全量读数由本流跑） | `slice-closeout` |
| 文档检查命令 | `formal-docs-landing` |
| 三层正式文档的位置 | `formal-docs-landing` |
| 统一语言与领域对象的位置 | `requirement-and-invariants`、`domain-impact-analysis` |
| 形式化工具链与声明边界 | `formal-guard` |
| spec 与 plan 的项目模板 | `spec-and-plan` |
| 项目专有的清理项 | `cleanup` |
| 验收处（接受者读证据的地方，例如工单评论；没填为本程目录） | `cleanup` |
| 子代理的模型与档位政策 | `delegate-brief` |
| 交接信息包放哪（两段分会话时；没填放项目 tmp 下本程目录 `handoff.md`） | `single-session-dev-flow` |

外部依赖按 README 的依赖表装：pstack、ub-mode、mattpocock/skills。

## 回复

先答。最多一条示例提示，放代码块。说明答案来自哪个文件，给已安装路径。不替人开工，不问「要不要现在开始」。
