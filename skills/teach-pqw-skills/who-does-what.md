# 谁做什么

每个环节人与代理的分工。人要拍板的事只在定义期与交接期；交付期人只看汇报件和待决事项。

| 环节 | 人做什么 | 代理做什么 | 人要拍板的 |
| --- | --- | --- | --- |
| 开工 | 说目标、完成判据、已知事实、真实约束 | 复述目标与问题；判断够不够格，量明显超出一程时先说；把 13 个环节与交接期的四件事写进任务清单 | 够不够格的结论 |
| 1 需求与不变式 | 先答代理问的值不值得做：需求证据、现状、具体的人、最窄切口，对它的猜测答「对」或纠正；再回答追问：给用户什么能力、系统前后差别、永远要守住什么 | 先查已有的与拒绝过的，一轮问齐值不值得做并表态；把需求写成单子，追问到不变式，列出什么算不变式什么不算 | 做不做、做多大；需求与不变式单，不留「待定」 |
| 2 领域影响与顶层设计 | 确认重点、次要、连带领域的分级；确认要不要新领域 | 按 DDD 分析影响，给出总边界 | 分级表与总边界 |
| 3 技术调研与复用 | 对复用或自造的结论表态 | 找现成的库、相近系统、社区实现；自造的写四项论证 | 复用论证单 |
| 4 形式化守护 | 决定投不投形式化 | 识别四类触发，提出建议；确认后建模、证明，列转契约测试的清单 | 投入与否及范围 |
| 5 细化领域设计 | 看聚合、边界、公开接口的形状；对仓储设计表态 | 领域模型、对象关系模型、仓储与 I/O 设计 | 细化设计清单 |
| 6 正式落盘 | 看落盘决定表；文档评审的未处理项由人裁 | 判断正式文档还是以源码为文档，三层落盘，做确定性文档评审 | 落盘决定表 |
| 定约 | 认可这一程的 spec；回答它的待决事项 | 和人一起写 spec；待决事项先筛四层，只把产品规则、范围变化、破坏性契约、须人本人做的动作交给人 | spec 的承诺与验收标准 |
| 定程 | 说清什么时候回来、有多少时间上手验收；看切片大纲与分程建议 | 写切片大纲，做尺寸核对，不过就停在交出之前给分程建议；分程时写路线图 | 照分、改，或「就按一程做」；验收窗口 |
| 交出 | 确认核对单每项都过；夜间一程还要说停点与点名授权的动作；确认可以移开注意力 | 换一个新上下文问四个问题，逐项核对；写交接信息包，包里只有这一程 | 「可以走了」 |
| 7 plan | 不参与；可以看 | 从切片大纲起步写 plan，在本程边界内可以重切，不改承诺 | 无 |
| 8 前置消熵 | 不参与 | 整程上下文包、关键设计与技术验证；每切片的开工包 | 无 |
| 实施 | 不参与 | TDD，按[写代码的四条](../single-session-dev-flow/SKILL.md#写代码的四条) | 无 |
| 9 派发 | 不参与；看到该自己判断的事派了出去，说「这件事你自己做」 | 两个判据与派发门都过了才派；四样东西给齐，规格写进文件；原始结果写进文件，报告限行 | 无 |
| 10 定期回看 | 不参与 | 便宜档的哨兵子代理按一程预算定的间隔（见 one-lesson-rule 的[节拍](../one-lesson-rule/SKILL.md#节拍)）回看并发消息，主代理在停顿点处置 | 无 |
| 11 切片收口 | 不参与 | 六步确定性验收 | 两轮不收敛时，缩窄承诺或交人工复核 |
| 12 向人汇报 | 看汇报件：架构层面的变化、读数、还缺什么、等你决定 | 出汇报件，放系统临时目录 | 汇报件里「等你决定」的条目 |
| 13 清理 | 不参与 | 切片级与一程级清理，出交付声明，列待人验收；交付声明就是交回的东西 | 无 |
| 收回 | 回到设计会话；按交付声明的「待人验收」逐样上手验，把结果告诉设计会话 | 读交付声明，把验收结果记进路线图；打回的与截下来的变成下一程的输入或修订包；修订后面各程的边界；上一程没验完就要交下一程时提醒一次 | 验过还是打回；下一程交不交、先验还是先交 |

人离开后需要回来的只有三种情况：汇报件里有「等你决定」的条目；spec 的待决事项列了缺口；收口两轮不收敛要人工复核。其余都不需要人在场。到了自己说的回来时刻，回到设计会话，先验「待人验收」，再交下一程。交付中想加范围，交付会话不在这一程里谈，它记成下一程的输入，收回时由设计会话和你定。
