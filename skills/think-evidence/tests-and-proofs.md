# 用确定性证据说话：测试与证明

## 两者各守什么

- 测试只能发现缺陷，不能承诺没有缺陷。证明与模型检查可以在它的前提与上界内承诺没有这一类缺陷。所以证真交给证明，证伪交给测试，两者不互相替代。
- 模型通过的只是模型与上界，不是整个系统。说清验证了什么、在什么前提和上界下、留下了什么。
- 数学论证、有限模型、机器证明与真实实现的符合性分开记录，不混成一个「已证明」。做法归 `formal-guard`。

## 先看它变红

- 新测试先在改坏的代码上跑一次，看它变红，再还原看它变绿。一次就绿的测试，不知道它守住了什么。
- 手工变异：改坏一处，记下哪条测试变红、退出码多少，按字节还原。交回与收口都附这张表。
- 形式化的检查也一样：先在一个故意破坏的变体上证明它能失败。
- 测量用的工具与夹具自己也要能失败。不在夹具里补造产品行为，再用它证明产品有这个行为。

## 判据从哪来

- 判据取自契约与 spec，不取被测实现自己报的结果。只断言「回调被调用了」，不算验证了行为。
- 不降阈值、不删断言、不跳过用例、不把预期的错误标成成功来换通过。
- 证据的具体要求与命令归 `slice-closeout`「对照 spec 与不变式」。
