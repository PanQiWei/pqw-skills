# 诤友：夜间一程

人会睡觉，代理不会。人在睡前交一程给代理夜里做完，这是允许的。它的本质是：人的反馈被固定推迟了八小时左右，这段时间没人能回答、没人能验、没人能叫停。要防的是代价随这八小时放大的东西。

| 要防的 | 为什么夜里更糟 | 防法 |
| --- | --- | --- |
| 偏离 | 白天一小时能拉回，夜里要到早上才发现，一夜的量全成沉没成本 | 夜里只做机器自己判得出对错的活：定义已在白天做完并经人确认，验收标准是测试、证明、读数。要人看一眼才知道方向对不对的活不放夜里 |
| 因为夜长就贪多 | 八小时可用，容易想填满 | 一程的大小仍由人早上验得完多少决定。做完就停，不自己找新活 |
| 只有人能定的事 | 干等则一夜白费，替人定则越权 | 睡前一次问齐；夜里新冒出来的只停依赖它的切片，其余照常，早上列出 |
| 不可逆与对外的动作 | 出错没人拦 | 只做人睡前点名授权的动作，授权不外推到相近的动作；没点名的准备到最后一步之前停下，留差异给人看 |
| 兜圈与故障 | 没人看见，烧掉额度与机器；进程或会话断了没人重启 | 两轮不收敛就截程交付；进度每一步写回 plan，后台任务脱离会话，断了能接上 |
| 早上的人被长报告带着走 | 刚醒，读到「全部完成」容易就信 | 晨间交付第一行写有什么等人决定；每样交付写怎么上手验、要几分钟、证据在哪；没做的与跳过的明说 |

## 睡前交接

人说要去睡时，在交出之前用固定格式核四样，各一句：

1. 做到哪里停。
2. 点名授权了哪些不可逆或对外的动作。
3. 还有哪些只有人能定的事，现在就问。
4. 早上有多少时间验收。

四样里缺的，提醒一次。人说「你看着办」时，把自己打算怎么办说出来，请人确认一次，不把模糊的话当成全权。四样写进交接信息包「起点与风险」的停点、点名授权的动作、人的验收窗口三行与「只有人能定的待决」一节；交付时再抄进 plan「预算与回看」的对应两行。

## 晨间交付

晨间交付是一种汇报件，格式归 `progress-artifacts`。

人这一侧对应三种问题：睡前贪多、授权模糊、醒来不验就接着提新的。三处各提醒一次，人定了就照做。
