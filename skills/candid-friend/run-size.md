# 诤友：一程的大小

一程该有多大，不由代理做得动多少决定，由人在有效精力时段里验得完多少决定。代理做出来、人还没验过的东西是**没验收的库存**。超了人的窗口，办法是分程，不是把切片切得更细。为什么验收产能是瓶颈、为什么切得更细缩不短回路：转手会丢信息，回路越紧越稳，一块多大由接的一方验得完多少定。做法加载技能 `think-closed-loop`。

## 人的验收窗口

交接点上问人两个数，各一句：你什么时候回来看？回来之后，你有多少时间上手验收这件事？两个数合起来叫人的验收窗口，例如「明早九点回来，验收一小时」。它写进交接信息包与 plan 的「预算与回看」。人不答时按缺省：当天回来，验收一小时。

## 尺寸核对

plan 写完之后、第一个切片动手之前，核三件：

1. **做得完吗。** 预计收尾在人回来之前吗？预计收尾要带依据；有上一程的，按上一程「实际用时比预计用时」的倍数修正。
2. **验得完吗。** 每片「人怎么验」写的分钟数，加起来在人的验收时间之内吗？
3. **每片都验得了吗。** 有没有哪一片做完之后，人没有任何办法上手看到它？这样的片只是中间产物，并进能看到的那一片。

三件都过，开工。任何一件不过，停在动手之前，用固定格式说一次，并在 plan 末尾写「分程建议」一节。入口处只粗判：需求明显是几天的量时，第一条回复先说一句「这可能要分几程」，不等到这一步。

## 分程建议

分程不是把切片表切成几段。每一程都满足四条：

- **自己有价值。** 做完这一程就停，人手里有一样能用的东西。
- **人能上手验。** 这一程的结果在一个验收窗口里验得完。
- **先做最可能改方向的。** 最不确定、最可能让人看了之后改主意的部分排在第一程。它验过了，后面的程才有依据。
- **后面的程只定到边界。** 第一程定到 spec 与 plan；后面的程只写一句目标，和它依赖第一程的什么结论。第一程验过，再给下一程做定义。

每一程写目标、交付的行为、预计时长、人怎么验。人看了可以照分，可以改，也可以说就按一程做。

人说就按一程做：照做，在处置记录里记一行，带上人的原话和「按一程做」四个字，`check-plan` 认这一行。之后按原计划推进：不收紧哨兵，不加检查，不在后面的汇报里反复提。汇报件里「没验收的库存」一栏每一程都有，不因为人越过了提醒而多写或少写。
