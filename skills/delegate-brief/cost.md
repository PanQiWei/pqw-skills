# 派发简报：钱是怎么花的

一段工作放在主上下文里做，和派给一个子代理做，各花多少，按报价算得出来。下面几条结论有的反直觉，「怎么派才便宜」的八条就是从这里来的。

## 数据从哪来

价格取自 Anthropic 的报价，缓存日期 2026-11-03。报价会变，用之前按现价核对一遍，比例变了，结论跟着调。订阅额度是不是按同样的比例消耗，没有查到明文，下面按报价的比例推断。

## 报价里要记住的几个数

以顶档模型为例，每百万 token：

| | 价格 | 是基础输入价的几倍 |
| --- | --- | --- |
| 输入（不走缓存） | $8 | 1 |
| 写缓存（5 分钟档） | $10 | 1.25 |
| 写缓存（1 小时档） | $16 | 2 |
| 读缓存 | $0.20 | 0.025 |
| 输出 | $40 | 5 |

写缓存比读缓存贵 50 到 80 倍，这是整件事的支点。各档的基础输入价：顶档 $8，默认档 $4，经济档 $2，最便宜档 $0.10；每档取报价当时一个代表模型的价，哪个模型算哪一档由项目接入点定。顶档的单价是经济档的四倍。

## 一个 token 在主上下文里要花多少

主代理的上下文是一条越来越长的前缀。每一轮，前面的全部内容读一次缓存，新增的内容写一次缓存。所以一个 token 进了主上下文，花的是：写一次，再在之后的每一轮各读一次。

按顶档、1 小时档算，每百万 token：

| 这个 token 之后还要陪跑多少轮 | 总价 |
| --- | --- |
| 0 轮 | $16 |
| 100 轮 | $36 |
| 300 轮 | $76 |
| 1000 轮 | $216 |

同样这些 token，让一个子代理读完就扔，1 小时档的写入价：默认档 $8，约为主上下文陪跑 300 轮的九分之一；经济档 $4，约十九分之一；最便宜档 $0.20，约三百八十分之一。这就是「读得多、读完就不用了」的活该派出去、而且该派给便宜档的原因。

## 子代理的开工费

每个子代理开工都要从头写一遍自己的上下文：系统提示、工具定义、简报、它要读的文件。它读不到主代理的缓存，因为缓存按模型隔离，前缀不同也读不到。所以：

- 小活不派。活本身只有几千 token，派出去光开工就花掉几万。
- 主代理读过的东西，子代理会再读一遍。简报写明先读什么、读到哪停。
- 几个小活合给一个子代理，开工费只付一次。

## 三个坑

1. **带着全量上下文分叉最贵。** 分叉继承主代理的整个上下文。前缀对得上时它每一轮读一次全量缓存；对不上时，整个上下文按写缓存的价重付一遍，之后每一轮都背着它。例：主上下文有五十万 token，分叉一次，光重写就是 $8，分叉之后每一轮再读一遍这五十万；同样的活交给一个新开的子代理，带一份写在文件里的几千字规格，开工只写几万 token，少一个数量级。
2. **干等会让主代理自己的缓存过期。** 缓存有寿命，5 分钟或 1 小时。主代理派完活停在那里等，超过寿命，下一轮整个上下文按写缓存的价重付。派出去之后接着做不依赖它的事，既不浪费时间，也保住缓存。
3. **报告会在主上下文里陪跑到最后。** 子代理交回的每个字都进主上下文，之后每一轮都要读。一份三千 token 的报告，在一个还有几百轮的会话里，比它看上去贵得多。所以原始结果写进文件，报告只带结论、指针和偏离，主代理按需去读文件。

## 记账

plan 的子代理表有一列 token，数从完成通知里抄。一程结束时看得见钱花在哪，下一程定档位与拆法有依据。
