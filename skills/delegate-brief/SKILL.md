# 派发简报

主代理自己做是默认，派子代理是例外。派了就要让子代理不丢上文、不越界、不自报成功。

## 派发门

派之前答三问，三个都不是就自己做。简报第一行写命中的是哪一条。

| 理由 | 判据 |
| --- | --- |
| 主上下文已膨胀退化 | 能指出退化的迹象：重复读同一文件、忘了早先的决定、回答变短变糊；或这份工作要读的量明显会把主上下文填满 |
| 需要新鲜且用完即弃的上下文，并且能并行 | 这份工作读的东西主上下文不需要，做完就能扔；或几份互不相交的工作能同时跑 |
| 主代理在这类工作上选不对工具或被冲突指令卡住 | 同一类错误已经出现过两次 |

不派的典型：单条依赖链、一个上下文装得下且没有长尾的工作、已经指到文件与行的单点修复、目标已知的查找。要新设一种子代理，先试试把它的做法写成技能让主代理自己按需加载，试过不行再设。角色数量只减不增。

## 四样东西缺一不可

1. **清晰的目标与指令。** 端到端要做成什么，从使用者视角写；完成即止。
2. **行动边界。** 写范围写成路径，每个路径带推出依据；不改的调用方写理由与停止条件。禁写清单。本闭包特有的停止条件。能用宿主的权限和门禁实现的硬限制就不靠提示词。
3. **必须遵守的规格。** spec 的相关节、不变式、细化设计里的类型与签名。指针，不内联大段。
4. **参考用的信息包。** 整程包与本切片开工包的路径；先读什么读到哪停。

缺任何一样，子代理的行动就不可控、难预测。填[派发简报模板](brief-template.md)。

写范围这样推：在基线上从要改的符号或文件出发，找调用方、导入方，以及读取它的测试与文档；要改的进写范围，不改的写理由与停止条件。两个子代理并行前，先点名它们争用的文件、类型或资源，点不出来就并行；写范围两两不相交。一个子代理不同时承担几个成员的实现、用例、文档与证据，范围大时拆开。

## 前置环境

派发者备齐工作树、分支、基线、依赖、构建产物与环境变量，写进简报。子代理进场后核对检出，不装依赖。日志与临时文件写进简报给的过程目录，不写在被跟踪的目录里。借用别的工作树里的东西之前确认没有写者在改它，借用只读。

## 模型与档位

从项目接入点取模型与档位政策；没有政策时按工作性质定：

| 工作 | 档位 |
| --- | --- |
| 纯读的调研、上下文包整理 | 便宜档 |
| 单模块、规格完整的实施 | 经济档，高推理 |
| 跨模块、契约留有判断余地、安全敏感 | 默认档，高推理 |
| 内核原语、生命周期、并发与跨进程故障、细微算法 | 顶档，高推理 |

默认从策略给出的档起步，纠偏不行先升推理档位，再升模型。写者、评审者与验收者不用便宜档。

## 等待与追加

- 等完成通知，不轮询。等的同时推进不依赖它的工作。
- 主动看长跑的子代理。记下每个子代理的开始时间。跑过 10 分钟的，用工作树事实看进展：提交、状态、改动统计、产出目录的修改时间、日志尾部。不读子代理的会话记录。到 30 分钟及其整倍数时按 `one-lesson-rule` 检查健康度。
- 越界、方向偏、卡在同一失败、范围蔓延或在做测不出结果的工作时，追加要求。每条追加先写进简报的「追加记录」再发出，验收按原简报加追加记录判断。
- 要立刻改变做法就停掉它，自己接手或带完整范围重派；它在收尾就让它做完。
- 同一闭包的追加可以续用原子代理；新一轮修复、换人与升级一律新开，新简报带上原简报、追加记录与上一轮报告。
- 子代理中途停下没交回时，读工作树判断做到哪一步，写接续简报，保留它的改动。
- 完成通知只表示通知送达。用工作树事实核对：分支头、提交与日志。

## 交回

要原始结果加指针：结论一句话；提交号；改了哪些文件各改了什么；验收逐项的命令、退出码与关键输出；门禁日志的时间与所跑的提交号；变异表；没覆盖到的项和自己做的决定。不要只给摘要。主代理自己读产物再下结论，不把子代理的结论直接当事实。验收只认 spec 的标准，不认子代理对自己工作的报告。

交回里有待定项时逐项分类：能自己定的写依据；只有人能定的写为什么。

## 验收防作弊

验收者不是写者。写新测试先确认它变红。简报要求写者为每条新测试做一次手工变异，按字节还原，交回时附变异表：改了什么、哪条用例变红、退出码。不接受放宽或删除已有断言的交付，简报明确要求改写的除外。验收失败先在基线上复跑同一检查，分清新失败与旧失败。

每条缺陷归写者、规格或环境三者之一，依据是独立验收报告或派发者在写者分支头的复跑。规格缺陷由派发者修规格，并记追加记录。

## 派评审者时

评审者只做确定性核对：给它 spec、不变式、改动与读数，让它逐条核承诺有没有做到。只给证据路径，不给派发者的结论。不派「找问题」「挑战设计」的对抗性评审，那种评审的上下文和实施方不对齐，带来过度设计和鸡毛蒜皮。只读评审只在本工作树内搜索。缺字段的报告不判通过。

## 升级

两轮修复不收敛时，先质疑判定本身是否正确、合理、本阶段必需。仍要修的，按起点档位选路径：起点是贵档，提高推理档位或由更强的模型接手，接手者先从更高视角分析根因再修；起点是便宜档且时间允许，丢弃原成果由强模型从基线重做，原分支只作对照。记下所选路径与理由。

## 合回

子代理只在自己的分支提交，不推送、不合并。派发者从子代理的本地分支合回：先读 diff，再在它的分支头复跑门禁，然后合并。合回后按 `cleanup` 清理它的工作树与分支。

## 派哨兵时

`one-lesson-rule` 的哨兵是一类固定的只读子代理：便宜档、后台常驻、自己计时、只写汇报目录。简报填[哨兵简报模板](sentinel-brief-template.md)，四样东西与普通简报相同，边界里多一条读入上限，规格里写清对齐层面与四问的判据。派出去之后在 plan 的子代理表记一行，状态写轮数。

## 撤掉或合并一种子代理

带与不带各跑一遍同样的切片，比哪些验收项翻转了，不比总分。跑两次以上再下结论。一次只改一处。

## 外部技能

- 派发的流程加载技能 `pstack:poteto-mode` 中的子代理章节。
- 并行扇出多个子代理并汇成一份报告，加载技能 `pstack:swarm`。
- 并发写同一文件、分支或状态之前先消除共享，加载技能 `pstack:principle-separate-before-serializing-shared-state`。
