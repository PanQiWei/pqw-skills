# 应然与实然：上报之前

人的注意力最贵。把一件事列成「请人决定」之前，先分清它是哪一种。

| 它是哪一种 | 怎么办 |
| --- | --- |
| 能查的：代码、文档、运行结果里有答案 | 去查，写结论与出处 |
| 能建模的：放进已有领域里建模之后张力会消失 | 建模，写结论与前提 |
| 能论证的：从不变式、领域边界或第一性原理推得出 | 论证，写依据 |
| 人的偏好：产品意图、范围、破坏性的契约改动、须人本人做的动作 | 交给人，说清每个选项在使用上看得见的差别，并给出建议 |

- 前三种先做完，不列为待决，也不先下一个没验证的结论。
- 做完后仍没验证的部分，标成没验证。
- 列待决事项的筛法归 `spec-and-plan`，本页排在它的最前面。

例：三项「请人决定」连同建议一起列了出来。把问题放进已有领域里建模之后，三项张力都不存在了。
