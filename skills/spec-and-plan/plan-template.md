# plan 模板

方法按 Matt 的 `to-tickets`：切成端到端的薄切片，每片能单独验证、能在一个新上下文里完成，前置的预重构先做，每片写明被谁阻塞。本模板在它的骨架上加入机读的进度总览、每个切片的开工包四节和里程碑待办清单。

使用规则：

- 放在项目 tmp 下本程的目录，与同目录 `spec.md` 配套。切片在本程内顺序做。
- 和 Matt 原版不同，本计划写成员、文件与验收命令，因为主代理在当前仓库执行。
- 每条验收标准都要落到某个切片和一条验收命令。
- 进度总览格式固定，哨兵与汇报件直接读它。每完成一步立刻改，不攒到收口。
- 项目有自己的 plan 模板时以项目的为准。

## 进度更新规则

1. **进度条一行。** `进度：[■■■■□□□□□□] 2/5 切片已完成 · 更新 <UTC 时间> · head <短 sha>`。10 格，已完成 ÷ 总数向下取整。跳过的切片不计入总数。
2. **当前一行。** `当前：切片 <号> <里程碑名>`。受阻时写 `当前：受阻于切片 <号>：<一句原因>`。
3. **切片表。** 状态只用：`待做`、`进行中（<里程碑>）`、`已完成 <提交号>`、`受阻（<原因>）`、`跳过（<理由>）`。
4. **子代理表。** 只有派了子代理才写。状态只用：`进行中`、`待验收`、`已合回 <提交>`、`已丢弃`、`停下（<原因>）`。
5. 进度条、切片表与提交历史不一致时，以提交历史为准，先改计划再继续。
