# 结构读数与差分变异的模型

与语言无关的定义。自带的工具按这份模型实现，语言适配器只负责把源码变成这里的对象。定义取自 Robert C. Martin 的 crapper 与 mutator（0BSD），计分单元的划分取 omne 的做法。

## 对象

| 对象 | 字段 | 含义 |
| --- | --- | --- |
| 单元 Unit | path、namespace、name、startLine、endLine、startByte、endByte | 一个计分单元：有名字、有函数体的函数或方法。限定名 `namespace.name`。单元之间可以嵌套，行范围内扣掉更内层单元的行才是它自己的行 |
| 判定 Decision | kind | 语法树上使控制流分叉的节点。集合 D 由语言适配器声明 |
| 行命中 LineHits | file → line → (covered, total) | 覆盖率报告里每行的命中。lcov 的 DA 记录是 (hit > 0 ? 1 : 0, 1)，BRDA 记录按行聚合成分支的 (covered, total) |
| 位点 Site | file、unit、line、anchorLine、start、end、original、mutant、category | 一处可替换的文本。anchorLine 是所在语句的起始行，多行语句只有这一行有覆盖记录 |
| 裁定 Verdict | killed(reason?)、survived、uncovered、notRun(reason) | 一个位点跑完的结果。killed 的 reason 可为 timeout；notRun 的 reason 取 noTests、crashed、budget、baselineFailed |

## 定义

- **圈复杂度** `CC(u) = 1 + |{d ∈ D : d 在 u 自己的行内}|`。更内层单元里的判定不算在外层头上。
- **认知复杂度** `CogC(u)` 按 SonarSource 白皮书三条：每个分叉结构 +1；嵌套在另一个分叉结构里的结构再加嵌套深度；同一表达式里逻辑运算符每换一种 +1。`else if` 与链尾的 `else` 各 +1 且不加嵌套，所以 `if … else if … else` 记 3。适配器声明哪些节点是分叉结构、哪些增加嵌套。
- **带位** 每个单元按两条线归到 ok、warn、alert 三档之一；圈复杂度的线总是看，CRAP 的线只在算得出时看，都没过线而 CRAP 算不出的记「无覆盖」。缺省线：圈复杂度 warn 10、alert 12，CRAP alert 30，严格大于才过线（CC 11 是 warn，13 是 alert；CRAP 31 是 alert，30 是 ok）。线可由调用方覆盖，读数 JSON 的 `thresholds` 记实际用的线。带位只是报告的标记，不是接受判据；过线的单元怎样交代归 `slice-closeout` 正文。
- **覆盖率** `Cov(u) ∈ [0,1] ∪ {null}`，三态：有值；未提供（没给覆盖报告）；无数据（报告里没有这个文件，或 u 自己的行上没有任何记录）。有记录时：有分支记录就取分支的 `covered / total`，否则取行记录的 `covered / total`。后两态 Cov 为 null，并带原因；不写成 0，因为 0 是「跑了测试一行没碰到」，与「不知道」是两回事。报告里找文件照 crapper：全等优先，否则整段路径后缀匹配（任一方向）恰一个才取，多个候选记「多个文件匹配」不猜。报告的可信度有三条警告，写在抬头与 JSON 的 `warnings`：报告早于被度量的改动文件（行号可能错位）；改动函数全部零命中（可能没跑到或报告过旧）；多个文件匹配同一路径。
- **CRAP** `CRAP(u) = CC² × (1 − Cov)³ + CC`，Cov 为 null 时 CRAP 为 null，报告 CRAP 列写「无覆盖」，覆盖率列分别写「未提供」或「无数据」。
- **基线比** 每个改动函数带基线版本同限定名单元的圈复杂度与认知复杂度（基线没有记 null）与趋势：新出现 new；圈复杂度涨 up、降 down；相等再看认知复杂度；都相等 same。变差 = 带位过线（warn 或 alert）且趋势是 new 或 up。报告全部列出，变差的标出并排前面；收口只逐条交代变差的，其余只列不解释，不替历史交代。CRAP 不比，因为基线的覆盖率拿不到。
- **不度量的文件** 非源码、声明文件、测试文件不进改动函数表，列进「未覆盖的改动文件」带原因。测试文件的匿名用例回调全并进 `<module>`，覆盖报告又通常不含它，读数没有意义。
- **单元摘要** `Digest(u) = sha256(u 自己的各行去尾部空白后以换行拼接)`。同名单元按行号顺序把各自摘要拼起来再取一次。摘要相同就是函数文本没变，挪位置、上方加行都不算变。
- **改动单元** 基线 ref 到工作树的 diff 碰到的行所在的单元。只认 Git ref，不认任务绑定。
- **纯删除** 只删不加的改动在新一侧没有行，记删除点前后两行（删除点前一行与后一行，文件头删除记第 1、2 行），所以删掉函数里一行也算改了这个函数。
- **基线** 显式给的 ref 要是 HEAD 的祖先；基线分支前进过时改用它与 HEAD 的合并点，抬头写明，JSON 的 `baseGiven` 记给的提交。没给 ref 取与目标分支的合并点。读数只认 `--repo` 所在仓库，会把 git 指到别处的环境变量（`GIT_DIR` 等）一律剥掉。

## 变异

- **引擎** 只有一种：Stryker。项目要用 vitest（根下有 `vitest.config.*` 或 `vite.config.*`，或 package.json 声明了 vitest）且找得到 `@stryker-mutator/core` 与 `@stryker-mutator/vitest-runner`；依赖按顺序找：项目根 `node_modules`、`--stryker-modules` 或环境变量 `PQW_STRYKER_MODULES` 指的目录、本技能 `scripts/node_modules`（`scripts/package.json` 钉版本，`npm ci --prefix <该目录>` 装）。不满足退出 2 并说明（jest、node:test 等运行器暂不支持）。抬头在基线说明之后写一行「引擎：Stryker <版本>（vitest）」，JSON 顶层 `engine: { name, version, runner, reason, notes }`。分工：范围（改动行、点名文件、基线）、资源（份额算并行度）、读数（四类裁定、测量无效、未覆盖段、存活清单、抬头与 JSON 字段）、增量指纹与超时复核由本工具做；位点生成、写入变异体、跑测试、还原由 Stryker 在 `.stryker-tmp` 的副本里做：一次性插桩全部变异体、测试进程常驻、按逐条覆盖只跑碰到变异体的用例、几个进程并行。Stryker 不改项目文件，只写 `.stryker-tmp`（跑完删，被 SIGINT、SIGHUP、SIGTERM 结束也删，只有被强杀时留下；没被项目忽略时抬头提醒）与系统临时目录的工作目录（`pqw-mutation/<仓库根哈希>-stryker/`：配置、报告、日志、增量文件、指纹记录）。
- **范围** 从 Git 算基线到工作树的改动行，扩成改动行所在有名单元自己的全部行（扣掉嵌套单元），写成 `mutate` 条目 `路径:起-止`；不在任何单元里的改动行原样；点名文件整份写路径。只收落在范围里的变异体。
- **位点** 读 Stryker 的 JSON 报告，每个变异体映射成一个位点：文件、所在单元（按行找）、行、原文（按 1 起的行列从源码切）、替换、类别（变异器名去掉 Operator、Expression、Literal、Declaration、Statement、Chaining 后缀后小写）、裁定、原因、`strykerId`。位点 id `文件:单元:单元内偏移:类别:替换`。
- **类型位置** Stryker 自己不变异类型节点；本工具按行找单元时把类型别名与接口当单元之外。
- **状态映射** Killed→杀死、Timeout→杀死（timeout）、Survived→存活、NoCoverage→无覆盖、RuntimeError、CompileError、Ignored、Pending→未跑带原因；映射表没有的状态记未跑「未知状态 X」并使整次测量无效（原因写出状态名），不猜。
- **超时复核** 第一轮报告里状态是 Timeout 的变异体，按所在的整行写成第二轮的 `mutate` 条目（`文件:起行-止行`，相邻行合并；用整行而不是行列，避开列号基数的歧义，同行别的变异体顺带再跑），一个工作进程、时限放宽（缺省第一轮 `timeoutMS` 的 4 倍且至少 60 秒，`--recheck-timeout` 可改），不进增量；第二轮的结果按位点 id 并入第一轮超时的位点（两轮之间 Stryker 重新编号，`strykerId` 对不上）：Killed 记杀死、Survived 记存活，原因都记 `recheck`；仍 Timeout 记杀死（timeout）；别的状态或对不上的保留第一轮裁定并计入未复核。抬头在计数后写「；复核 N（超时转杀死 a、存活 b、仍超时 c）」，有未复核再加「、未复核 d」；JSON 顶层 `recheck: { total, killed, survived, timedOut, notRun, seconds } | null`；没有超时不起第二轮；`--no-recheck` 不复核。第二轮失败（退出非零且无报告）不影响第一轮裁定，引擎说明里写「复核未完成」，全部计入未复核。
- **点名文件** 调用方点名的文件整份写进 `mutate`，不论基线到工作树有没有改动，位点带 `pinned`；点名的文件不列未覆盖段，因为它不是按改动打的。用于判据与状态机所在的文件：改动在别处，但这些文件的测试是否守得住要一起看。
- **增量** 配置开 `incremental`，增量文件在工作目录；指纹（工具版本、「vitest@<版本> + <配置文件>」、测试文件摘要、Stryker 版本）记在同目录，与上次不同就 `force` 整轮重跑；因为放宽或删掉一条断言后，上次的「杀死」就不再可信。沿用的个数从 Stryker 日志的增量摘要行取，抬头写「沿用 N」；首轮没有沿用时写「增量：已开，本轮没有沿用」，指纹变了写「增量：指纹变了，整轮重跑」。结果 JSON 带 `fingerprint` 四项与 `incremental: { file, force }`。
- **初跑** Stryker 先在未变异的副本上跑一遍全部用例，`baseline.seconds` 记它的用时（从日志取）。初跑失败（退出非零且无报告）退出 1，抬头写「测量无效（Stryker 初跑失败）」并在「基线不通过：」下给日志尾与完整日志路径。
- **存活清单** 只陈述事实：哪个位点、原文换成什么、测试仍过。怎么处置归读的人。
- **分数** `killed / (killed + survived)`，没有已执行的位点时为 null。
- **测量无效** 初跑失败，或报告里有未知状态，或一个位点都没有执行（杀死加存活为 0：没有位点、全部位点无覆盖、没有执行任何位点），`valid` 为 false 并带原因，分数为 null，抬头写「测量无效（原因）」且不出四类计数。没有执行过的测量不能写成「杀死 0、存活 0」。只列时 `valid` 为 null。
- **未覆盖段** 范围里没有变异体的段单独列出，不进分数，带所在单元名（模块级为空）。分数满不代表改动都被打过。

## 资源

变异工具是机器上的重型任务，要给同机的别人留份额。与语言和测试运行器无关的部分如下，参数名与缺省见命令面的 `--help`。

- **容量** 启动时量：逻辑 CPU 数、可用内存（MB）、1 分钟负载。
- **份额** `1 / (同机另有的重型任务数 + 1)`。任务数由调用方声明，缺省 0。
- **并行度上限** `max(1, floor(CPU 数 × 份额))`；可用内存低于阈值时再减半（仍至少 1）。
- **并行度** 缺省等于上限；调用方显式给的并行度超过上限按上限，并在输出里写明。写进 Stryker 配置的 `concurrency`，启动时定下，运行中不调；复核那轮固定 1。
- **优先级** Stryker 进程以较低优先级启动（能设的平台才设，设不了写明）。
- **量法** 一轮耗时约等于初跑一遍加每个变异体只跑碰到它的用例，位点数与测试时长的影响远小于「位点数乘整套测试一遍」的旧做法。读数（同一仓库 pqw-skills、同一范围 `skills/slice-closeout/scripts`、整套测试约 25 秒）：0.7.0 的内建引擎在第七程的一个切片 106 个位点，15 分钟预算只跑完 36 个；0.8.0 的 Stryker 在第八程切片 02（基线 3623f97）308 个变异体 70 秒跑完，分数 90%，没有超时；切片 03（基线 2e8d158）233 个变异体第一轮 47 秒，1 个超时复核 43.5 秒仍超时（是真死循环），分数 89%。两次都有一多半变异体无覆盖，因为命令面文件只在用例起的子进程里跑、逐条覆盖看不见，所以命令面要薄、逻辑进 lib。不同引擎的变异器不同，位点数与分数不能跨版本比。
- **记录** 结果 JSON 的 `resources` 节记容量、任务数、份额、上限、实际并行度、显式值与是否被降、低内存阈值与是否减半、优先级；跑过之后加 `timing`（一轮总耗时、复核耗时）。表格末尾一行资源摘要。耗时数字要能解释：被挤占的慢不是工具慢。

## 适配器要给的

| 适配器 | 输出 |
| --- | --- |
| `units(source)` | 单元列表，含每个单元的 CC 与 CogC |
| `sites(source, units)` | 位点列表 |
| `decisions` | 集合 D 的说明，写在适配器文件头 |

TypeScript 适配器：判定集合为 if、三元、for、for-in、for-of、while、do、catch、case、default、`&&`、`||`、`??`、`?.`；有名字的内层函数、对象字面量方法与类字段箭头函数各自成单元，匿名回调并入外层。
