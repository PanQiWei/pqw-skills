# 切片收口

收口是验收，不是挑刺。拿到的上下文是 spec、不变式、本切片的改动和读数，核的是承诺的有没有做到、守的有没有守住。填[收口清单](closeout-checklist.md)，六步按顺序，前一步红了不进下一步。

## 顺序

### 1 类型检查与 lint

主代理自己在候选头上跑，命令从项目接入点取。不论代码由谁写，都不采用写者报告的结果。有失败先修，不进下一步。

### 2 对照 spec 与不变式

只判 spec 已经写明的验收标准和不变式对照。每一条结论是达到或未达到；未达到的写明缺哪份证据或哪件产物。spec 没写的标准不补。形式化过的性质核契约测试是否在、是否变红过。实现有没有遵守已采用的架构、技术设计与规格：问题要带反例，或指出缺的行为，测试通过不代替这一面。

本程更正过的裁定与 spec 原文冲突的，另列「冲突项」：写裁定、与之冲突的 spec 原句。冲突项不是达到或未达到，由主代理改 spec 后再核。

证据要贴出来：命令、输出尾部、测量摘要或日志摘要。只写结论不算证据。

### 3 结构读数

只摘本切片改动函数的圈复杂度与 CRAP，工具与范围从项目接入点取，基线是本切片的起点提交。读数是抽查线索，CRAP 低不表示行为正确。命令失败时交回命令和输出，不手算冒充工具读数。改动不在度量范围内时写「未覆盖」，逐个列出未覆盖的文件，并给出标明是手算的替代证据。依赖方向的违规与环原样列出。

### 4 差分变异

固定要跑，命令与范围从项目接入点取；只在本切片的最终头上跑一次，修复轮一开始，就停掉旧头上还在跑的。范围只取热点：本切片的改动行所在的函数，加上判据、状态转移、并发与失败分支所在的文件。先只列范围，核对后再正式运行。存活与无覆盖原样列出；命令失败交回命令和输出，不把未跑写成零存活。把存活判为等价变异之前，先说明能否改夹具或代码让它可判定。

### 5 去 AI slop

调用 Skill 工具加载 `pstack:deslop`；写的散文调用 Skill 工具加载 `pstack:unslop`。

### 6 证明可用

在真实产物上跑一次本切片的行为：起服务、跑命令、打开页面，读实际的值。调用 Skill 工具加载 `pstack:principle-prove-it-works`。

## 两轮不收敛

连续两轮出现同一类阻断时，停止逐个补洞。先质疑判定本身：这一类承诺是否正确、合理、本阶段必需。不必需的缩窄承诺，工具对这一类不再下确定结论，交人工复核或按未达到记录。仍要修的按 `delegate-brief`「升级」换路径。

## 不做的

- 不做对抗性评审，不派子代理「找问题」「挑战设计」。对抗性评审的上下文和实施方不对齐，带来过度设计、过度优化和鸡毛蒜皮。
- 不为读数本身优化。圈复杂度高但行为正确、测试在，先记下，不在收口里重构。
- 不接受放宽或删除已有断言的改动，spec 明确要求改写的除外。

## 常驻要求

对自己和派出去的子代理同样要求代码品味、TypeScript 最佳实践、架构优雅与代码整洁。不过度设计，不过度优化。判设计与实践的依据是 ub-mode 的先做对再做好，调用 Skill 工具加载 `ub-mode`；TypeScript 的写法调用 Skill 工具加载 `pstack:typescript-best-practices`。

## 外部技能

- 对照标准的评审调用 Skill 工具加载 `mattpocock-skills:code-review`，只用它的标准面。
- 派只读评审者时按 `delegate-brief`「派评审者时」。

## 收口之后

切片级清理按 `cleanup`，向人汇报按 `progress-artifacts`，提交并更新 plan 的进度总览。
