# 切片收口

收口是验收，不是挑刺。拿到的上下文是 spec、不变式、本切片的改动和读数，核的是承诺的有没有做到、守的有没有守住。

## 顺序

1. 主代理自己跑类型检查与 lint，命令从项目接入点取。有失败先修，不进下一步。
2. 对照 spec 的验收标准逐条核，对照不变式逐条核；形式化过的性质核契约测试是否在、是否变红过。
3. 结构读数：只摘本切片改动函数的圈复杂度与 CRAP。读数是线索，不是结论。
4. 差分变异：只打本切片的热点，先 `--plan-only` 列范围再跑。存活与无覆盖原样列出。
5. 去 AI slop。
6. 证明可用：在真实产物上跑一次本切片的行为。

## 不做的

- 不做对抗性评审，不派子代理「找问题」。对抗性评审的上下文和实施方不对齐，带来过度设计、过度优化和鸡毛蒜皮。
- 不为读数本身优化。圈复杂度高但行为正确、测试在，先记下，不在收口里重构。
- 两轮同一类阻断不收敛时，停止逐个补洞，先问这一类承诺是否本阶段必需，再决定缩窄还是升级。

## 常驻要求

对自己和派出去的子代理同样要求代码品味、TypeScript 最佳实践、架构优雅与代码整洁。不过度设计，不过度优化。

## 外部技能

- 对照标准的评审调用 Skill 工具加载 `mattpocock-skills:code-review`，只用它的标准面。
- 去 slop 调用 Skill 工具加载 `pstack:deslop`。
- 证明可用调用 Skill 工具加载 `pstack:principle-prove-it-works`。
- 研发品味调用 Skill 工具加载 `ub-mode`。
