# 进展汇报件

人把注意力移开之后，靠汇报件把控进度、健康度并快速反馈。汇报件的目的不是留档，是让人的注意力停在架构、产品、交互体验三个层面，不下到技术与代码细节。

## 什么时候出

- 每次顶层回看之后，有变化就出一份。
- 每个切片收口之后。
- 一程交付时出最后一份，连同交付声明。

没有变化时不出。空汇报比没汇报更坏。

## 三种形式

| 形式 | 讲什么 | 怎么做 |
| --- | --- | --- |
| 架构图与 UML | 实现在架构层面长什么样，和之前比有什么区别，还缺什么 | Mermaid，前后对照两张图或一张图标出新增与改动。至多六个框，每框至多八个词。只在图能降低理解难度时画 |
| 快速 demo | 重要的产品功能让人直接上手 | 单文件 HTML，可增量更新：每个切片追加一段，不重写整页。做法调用 Skill 工具加载 `mattpocock-skills:prototype` |
| 进展文档 | 变了什么、还缺什么、待人决定什么 | 按[汇报件骨架](report-skeleton.md)写 Markdown；交互式网页版归下一程的工具 |

## 讲法

用追进度的讲法，调用 Skill 工具加载 `pstack:ketchup`：说变化，不说过程；说「测试过了」，不说「门禁绿了」；不写哈希、路径、命令、测试数，除非人要据此做决定。开头一句话说有什么等人决定，没有就说没有。待人决定的每一项给出自己的建议、依据和风险。不编造决定来填篇幅。

## 放在哪

统一放操作系统临时目录，各操作系统一致，借用系统的定期清理：

```
<系统临时目录>/pqw-skills/<会话标识>/<一程标识>/artifacts/
```

路径由 [`scripts/artifacts-dir.mjs`](scripts/artifacts-dir.mjs) 解析并创建，系统临时目录按 Node 的 `os.tmpdir()` 取值：Linux 与 macOS 通常是 `$TMPDIR` 或 `/tmp`，Windows 是 `%TEMP%`。会话标识从宿主环境变量取，取不到时由调用方传。汇报件不进仓库，不进项目 tmp。

要人看时直接在 IDE 打开，不只给路径。

## 清理

用完即弃。切片交付和一程交付后的清理归 `cleanup`，调用 Skill 工具加载它。要长期留的事实写进正式文档，不靠保留汇报件。
