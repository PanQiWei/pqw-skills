# 交接点核对单

交接期「交出」那一步用。交出的那一刻叫交接点，它是物理条件：长期维护的知识已进唯一源并过评审。人把注意力移开之前，设计会话逐项核。任何一项答不出，补，再核一次。

## 换一个新上下文问四个问题

找一个没有本次上下文的会话或子代理，只给它正式文档、定义期的单子与这一程的 spec，问：

1. 这一程从哪个提交开工，边界到哪里？
2. 系统要守住哪些不变式，每条由谁守？
3. 做到什么算完成？
4. 每条关键事实的出处与有效修订在哪里？

四个都答得出，并且答案与人的意图一致，才算过。答案写进[交接信息包](handoff-pack-template.md)的「四问」一节，交付会话拿到包就能对照。

## 逐项核对

- [ ] 需求与不变式单已由人认可，没有「待定」。
- [ ] 领域影响分级表每条不变式都指到一个领域或接缝；新领域有论证。
- [ ] 复用论证单有结论，自造的有四项论证。
- [ ] 形式化触发建议单由人确认；确认投入的，模型与证明已落盘并验证过能失败；不投入的写明理由。
- [ ] 细化设计清单：重点领域有聚合与边界，公开接口有类型与签名，有存储的四问有答案。
- [ ] 落盘决定表每项设计产出都标了「正式文档」或「以源码为文档」，正式文档已写进唯一源。
- [ ] 文档评审已做，五类判据无未处理项。
- [ ] 正式文档不依赖对话记忆：没有「如前所述」「按我们讨论的」一类指代。
- [ ] 正式文档引用的每个文件在起点提交上存在。
- [ ] 定约做完：这一程的 spec 已由人认可，`check-plan --spec` 退出 0。
- [ ] 改了既有承诺的，`consumers.mjs` 按 spec 的旧字面搜过，范围外的命中已补进责任分级或写明不受影响。
- [ ] 每条验收写明经过的成员，都在责任分级里，或写明按范围验收（`check-plan` 核）。
- [ ] 定程做完：切片大纲写进了包；人的验收窗口问过了：你什么时候回来看？回来之后，你有多少时间上手验收这件事？人不答按缺省「当天回来，验收一小时」。尺寸核对三件都过，或人说按一程做并记进了包的「已定事项」。看到人这一侧的风险就说一次：提醒、依据、建议、选择。做法加载技能 `candid-friend`。
- [ ] 分程时路线图已写，这一程标成已交出；只有一程时不写路线图。
- [ ] 包里只有这一程：没写后面还有几程、下一程做什么；「范围外」只说这一程不做什么，不说它归哪一程。
- [ ] 人要离开较久或交的是夜间一程时，停点与点名授权的动作问过了，写进交接信息包；人说「你看着办」时，把打算怎么办说出来，请人确认过一次。
- [ ] `check-plan --handoff <包>` 退出 0。
- [ ] 人确认可以移开注意力。
