# 从 Anthropic「把子代理折回主循环」吸取的经验

来源：Anthropic Applied AI 团队，Building agents: When to fold subagents into your main agent loop，2026-10-22，正文在 [claude.com](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)。整理时间 2026-11-07。下面先摘文章的结论，再写它落到本仓库哪两个技能、改成什么规则。

## 文章的结论

**默认形态**：一个模型、一个上下文窗口跑开放式工具循环，技能与工具按需渐进加载。在多个企业部署的比较里，这种形态在质量上常常同时胜过「一个大提示词」和「编排者加专家子代理」，而且成本与延迟更低。一个客户把多代理 harness 换成单循环，运行时间快了约 2 倍。文章把它当作默认起点去测，不当作普适定律。

**只有三种情况值得保留子代理**：

1. 单循环已经出现可测量的上下文膨胀导致的退化。
2. 并行工作，而且每份工作需要新鲜的、用完即弃的上下文窗口。
3. 单个代理选不对工具，或者系统提示里有互相冲突的指令。

**多代理在大组织里的失败方式**：交接时丢细节；子代理泛滥、没人拥有、没有标准；每个团队往系统提示里加规则变成「缝合怪提示」；各团队只优化自己子任务的评测，整体分数失真；延迟。文章还点名「按组织架构图造代理」是 Conway 定律在作怪。

**单循环的内部**：模型第一回合写计划，结果回来就修订，计划者与执行者是同一个模型，所以能中途改道。回合数、成本预算和写入门禁放在 harness 里。逻辑从代码搬进模型：顺序与领域流程进技能，硬限制（校验、审批门）与对话中的查询进工具，只有便宜且几乎总要加载的东西才留在代码里。

**工具与技能的分工**：工具用于动作、读实时数据、固定形状的结果；按用户意图分组而不是一个 API 一个工具，系统提示里超过 30 到 50 个工具定义后选工具就开始退化；前置条件放进工具，工具返回模型能照做的指令。技能用于编码一个团队怎样做事：步骤、规则、判断，由拥有者维护；用 `skill-creator` 写和审（删冗余、去重、重组），用 `skill-doctor` 量每个技能的成本与使用率并删掉没人用的。

**迁移方法**：先建评测，端到端一套加每技能一套，十个黄金样例就能起步；先合并紧耦合的专家；把子代理先降成工具作为过渡；然后一次折一个子代理，把它的提示变成技能、它的 API 调用变成工具，带与不带各跑评测，留好的那个。要看哪些任务翻转了而不只看总分：一个样本客服代理折掉发货专家后延迟降了，但送达日期检查坏了，主代理自己答了没去问；而且这个回归两次里只出现一次，所以每个任务要跑多次。文章的一句话原则：measure, change one thing at a time, and keep what holds up。

**保留的立场**：子代理在并行、验证、模块化权限上仍然成立，Anthropic 自己的研究系统也在用。

## 落到本仓库

这篇文章和本仓库的流是同一个方向：一个主代理在一个会话里走完，技能按需加载，子代理是例外不是默认。下面是从中抽出来的规则，分别进两个技能。

### 进 `single-session-dev-flow`

- **主代理自己做是默认。** 交付期的实施默认由主代理自己在一个上下文里做。派子代理是例外，必须说出三种理由之一。
- **计划者就是执行者。** plan 由主代理写，结果回来就修订，不交给别人规划再交给别人执行。切片开工包里的推进方案和里程碑清单是这份活计划的载体。
- **预算在流里，不在代理的自觉里。** 一程和每个切片都带回合或时间预算，到了预算就回看而不是继续跑。一堂课法则就是这个预算的实现。
- **评测端到端。** 切片和一程的完成只认 spec 的验收标准，不认任何子代理对自己工作的报告。
- **入口技能保持薄。** 入口只有路由、顺序、交接点、规则，不堆各环节的做法。往入口加一条规则前先问它是不是该归某个环节技能，否则就是缝合怪提示。

### 进 `delegate-brief`

- **先过派发门。** 派之前答三问：主上下文是否已经因为膨胀退化；这份工作是否需要新鲜且用完即弃的上下文并且能并行；主代理是否在这类工作上选不对工具或被冲突指令卡住。三个都不是，主代理自己做。简报的第一行写命中的是哪一条。
- **折回优先于新设。** 子代理的角色数量只减不增。要新设一种子代理，先试试把它的做法写成技能让主代理自己按需加载，试过不行再设。
- **交接零损耗。** 简报里给齐四要素是为了让子代理不丢上文；交回时要求原始结果加指针，不要只给摘要，主代理自己读产物。把子代理的结论直接当成事实就是文章说的「交接丢细节」。
- **先量后合。** 要撤掉或合并一种子代理，带与不带各跑一遍同样的切片，比的是哪些验收项翻转，不是总分；跑两次以上再下结论。
- **硬限制进工具，流程进技能。** 子代理的写范围、禁写、停点这类硬限制，能用 harness 的权限和门禁实现的就不靠提示词；流程与判断才写进简报和技能。

### 进 `AGENTS.md` 的维护规则

- 用 `skill-creator` 审技能：删冗余、去重、重组。
- 量每个技能的成本与使用率，没人用的删掉。宿主有 `skill-doctor` 一类工具就用它。
- 改一个技能后，带与不带各走一遍同一程，留好的那个。一次只改一处。
